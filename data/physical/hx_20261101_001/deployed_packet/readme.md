# Fixed-reference pilot — 2026-10-31
Purpose: describe three independent fan starts at the current untouched trial state. No tape movement, board reboot, new fixture, acceptance-percent tuning or automatic retry.
User declared apparatus fixed and Xshell available. Assigned fixture/mount IDs are session labels; physical installation is operator-declared, not independently verified. Mass/radius/environment/power/cable fields remain unknown rather than fabricated.
Fixed protocol: 30-second delay after the operator confirms fan ON, then 40-second capture, Z, unchanged AA128-to64, all 8x128-turn windows. Thirty seconds is a uniform delay, not proof of thermal or speed settling. Actual speed and configuration are recorded. Software loads the capture overlay and initializes the sensor for each run; board boot stays unchanged by plan.
Software is extracted into RAM. Raw files and reports are written to the USB after the original capture stops/drains; USB remains connected in the same way throughout all three runs. TF system-card inspection/repair is not requested. Nothing overwrites previous captures.
Default amplitudes are CPU references; this pilot does not generate new FPGA 1x arithmetic evidence. Existing verified hardware arithmetic remains separately archived. The PL synchronous capture is real hardware when executed by the user.
On an error or Ctrl+C, the script stops, retains the partial batch and attempts one archive export. No extra fan start is requested automatically. Only completed run summaries appear in batch_summary.json; failed run logs/raw remain in the archive.
This pilot measures the observed run-to-run range. It does not certify calibrated accuracy or automatically authorize correction. A/B/C and the planned reboot group remain deferred pending the pilot and the remaining time.
